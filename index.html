🔌 Plugin Architecture

RecCall's universal AI context engine uses a modular plugin architecture with dependency injection, making it easy to extend and integrate with any AI tool or platform.

🏗️ Core Engine

Centralized business logic with dependency injection

  • IContextStorage - CRUD operations
  • IRepositoryClient - Remote repository management
  • ICacheManager - Multi-layer caching
  • IRecipeValidator - Security validation
  • TelemetryManager - Performance monitoring

🔌 Platform Adapters

Thin wrappers around core engine for different platforms

  • CLI Adapter - Command-line interface
  • MCP Adapter - Model Context Protocol server
  • VSCodeAdapter - VSCode extension with core engine
  • Warp Integration - Terminal shell via CLI (uses core engine)
  • Browser Extensions - Web platform support
  • All platforms use unified core engine - Consistent features across all integrations

Dependency Injection Example

# Core Engine with DI import { createCoreEngine } from 'reccall/core'; const engine = await createCoreEngine(); await engine.initialize(); # Custom Storage Backend import { IContextStorage } from 'reccall/core'; class RedisStorage implements IContextStorage { async record(shortcut: ShortcutId, context: string): Promise { // Redis implementation } // ... other methods } # Register Custom Backend diContainer.register(TOKENS.CONTEXT_STORAGE, RedisStorage);

RecCall is built with a modular, extensible architecture that supports both local and remote recipe management with seamless IDE integration.

🖥️ Client Layer

Multi-platform client implementations for different development environments

  • CLI Tool (Node.js/TypeScript)
  • Cursor IDE MCP Server
  • VSCode Extension
  • Warp Terminal Integration
  • Shell Script Integration

📦 Core Engine

Central recipe management and execution engine

  • Recipe Storage & Retrieval
  • Context Processing
  • Command Execution
  • Cache Management
  • Validation & Security

🌐 Repository Layer

Remote and local repository management system

  • HTTP/HTTPS Repository Client
  • Local File System Storage
  • Recipe Caching & TTL
  • Manifest Processing
  • Version Management

🔧 Integration Layer

Platform-specific integrations and adapters

  • Git Workflow Integration
  • IDE Communication Protocols
  • Terminal Shell Integration
  • File System Operations
  • Network Operations

Data Flow Architecture

# RecCall Data Flow User Command → CLI Parser → Recipe Resolver → Context Processor → Command Executor # Repository Flow Repository URL → HTTP Client → Manifest Fetch → Recipe Download → Local Cache → Recipe Execution # IDE Integration Flow IDE Request → MCP Server → Recipe Lookup → Context Processing → Response → IDE Display

📋 Repository Schema & Structure

RecCall repositories follow a standardized schema for consistent recipe management and discovery across different hosting platforms.

Repository Structure

# Standard Repository Layout repository-root/ ├── manifest.json # Repository metadata and recipe index ├── recipes/ # Individual recipe files │ ├── git-workflow.json │ ├── deployment.json │ └── testing.json └── README.md # Repository documentation

Manifest Schema

# manifest.json Structure { "name": "Repository Name", "description": "Repository description", "version": "1.0.0", "author": "Repository author", "url": "https://contexts.reccaller.ai/", "recipes": [ { "name": "Recipe Display Name", "shortcut": "recipe-shortcut", "description": "Recipe description", "file": "recipes/recipe1.json", "category": "development", "tags": ["git", "branch", "feature"], "version": "1.0.0" } ] }

Recipe Schema
